# 04. 데이터 모델 / 파일 정책

## 파일 경로
```
Notes/
  Inbox.md                    # 루트
  Work/
    Plan.md                   # 한 단계
    Project/
      Meeting.md              # 두 단계
```
- 폴더 깊이는 `0~2`; 폴더의 이동/개명 시 UUID·중복 이름 검사 필수.
- **프로젝트(ADR-0005)**: 기본 프로젝트는 위 구조 그대로, 다른 프로젝트는 `Notes/@<프로젝트 이름>/<폴더 0~2단계>/<제목>.md`.
  폴더 이름은 `@`로 시작할 수 없음. 데스크톱 인덱스 `projects`(006)가 ID ↔ 이름을 연결하고, 화면이 프로젝트 목록을 저장할 때 폴더 이름을 맞춤.
- 사용자 파일명과 내부 ID를 분리. 외부 동기화의 안정적인 참조는 UUID.
- `.md` 또는 `.txt`만 허용, UTF-8, NFC 정규화 및 경로 탐색(`../`) 차단.
- **이름 규칙의 단일 기준은 `packages/protocol/fixtures/paths.json`** (웹 TS와 Rust core가 같은 파일로 테스트):
  - 금지 문자 `\ / : * ? " < > |`·제어 문자 → 제목은 `_`로 치환, 폴더는 거부.
  - Windows 예약어(`CON`, `NUL`, `COM1`… 대소문자 무시)는 제목 앞에 `_`, 폴더는 거부. 끝의 `.`/공백 제거.
  - `.`으로 시작하는 이름(숨김 파일)은 제목 `_`로 치환, 폴더는 거부.
  - 길이: 제목 200자, 폴더 한 칸 70자 (UTF-16이 아닌 **코드 포인트** 기준).
- 로컬 파일 저장(`crates/core` `FileStore`): 같은 폴더 임시 파일 → fsync → rename(원자적 저장). 루트 안 심볼릭 링크는 따라가지 않음. 3단계 이상 깊은 폴더, 다른 확장자, 숨김 파일은 목록에서 제외.
- 메모 제목 변경 시 경로도 재배치하지만 파일 내용 보존.

## 저장 테이블 (데스크톱 인덱스는 `db/sqlite/001~003` 구현됨: notes, edit_sessions, meta, history_stacks)
- `notes`: note_id, owner_id(서버), folder, path, format, content_hash, version, timestamps.
- `edit_sessions`: 시작/종료, 누적 활성 시간, 장비 ID, 최초/재개 구분.
- `local_history`: note_id, 순번, 변경 내용(델타), redo cursor, 저장 시각.
- `sync_events`: append-only 변경 기록, 서버 수신 상태, 일관성 토큰.
- `devices`: 계정에 속한 등록된 장비, 공개키, 마지막 접속.

## 편집 시간 (요구 23·24, 2026-11-04 사용자 확정)
두 값을 **각각** 기록하고 화면에 함께 표시합니다 (`작성 00:00:00 · 열림 00:00:00`).
- **작성 시간(`activeMs`)**: 키 입력 사이 간격의 합. 간격이 `idleAfterMs`(60초)를 넘으면 그 간격은 제외 → 쉬는 시간은 들어가지 않음.
- **열어둔 시간(`openMs`)**: 메모가 열려 있고 창이 화면에 보이는 동안의 시간. 다른 창에 포커스가 있어도 화면에 보이면 포함, 최소화/탭 숨김 동안은 제외. 절전 등으로 시계가 크게 건너뛰면 tick 2회분까지만 인정.
- **세션**: 메모를 연 시점 ~ 다른 메모로 전환·창 숨김·페이지 종료. 다시 보이면 새 세션(재개). 무입력만으로는 세션을 끊지 않음.
- 입력 없이 2초 미만 연 세션은 기록하지 않음(`minSessionOpenMs`). 열어둔 시간은 10초마다 저장.
- 강제 종료 시 마지막 저장 시각까지만 보장. 향후 monotonic clock + journal로 복구.
- 호환: v0.1 세션 레코드(openMs 없음)는 openMs=0으로 읽음.

## 유사 문서
- MVP: title/path/content의 길이 제한이 있는 검색. 온라인 서버에서 검색 실행.
- 1차 서버: PostgreSQL `pg_trgm`, 요약 인덱스, 사용자별 범위 제한과 증분 업데이트.
- 2차: 한국어 검색 품질 검증 후 형태소 분석기/embedding 벡터 인덱스 추가 고려.
- 브라우저/저사양 BSD 클라이언트는 서버에서 받은 상위 K건만 표시.
- 트리와 방사형 그래프는 최대 표시 노드 수 제한.
