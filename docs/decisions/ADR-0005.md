# ADR-0005: 프로젝트 (폴더 위 단계)
- 상태: **제안**, 2026-11-13. 사용자 요청: 사용 의견 9번 "프로젝트 생성으로 디렉터리도 구분". 방향은 "폴더 위 단계"로 결정됨.
- 배경: 지금은 계정마다 하나의 트리(루트 → 폴더 2단계 → 메모)만 있습니다. 업무나 개인처럼 주제가 다른 메모가 한 트리에 섞입니다.
  요구 #21(폴더 2단계)은 그대로 두고, 그 위에 "프로젝트" 단계를 하나 둡니다.

## 결정 (제안)
1. **프로젝트는 ID(UUID)와 이름을 가진 별도 기록입니다.** 메모에는 `projectId`가 붙습니다.
   - 메모처럼 이름과 ID를 분리합니다. 그래서 이름을 바꿔도 메모 기록이 흔들리지 않습니다.
   - `projectId`가 없는 메모(`null`)는 **"기본" 프로젝트**에 속합니다. 그래서 기존 메모는 서버와 웹에서 옮기거나 고칠 필요가 없습니다.
   - 이름 규칙은 폴더 한 칸과 같습니다(`paths.json`: 금지 문자, 예약어, 70자). 계정 안에서 대소문자를 무시하고 중복을 막습니다.
2. **폴더 2단계는 프로젝트 안에서 그대로입니다**(요구 #21). 예: `업무 프로젝트 / 회의 / 2024 / 메모.md`.
3. **화면**
   - 정리 영역 맨 위에 프로젝트 선택 상자와 "+ 프로젝트" 버튼을 둡니다. 트리, 검색, 메모 개수는 **선택한 프로젝트만** 보여 줍니다.
   - 마지막으로 고른 프로젝트를 기억합니다. 새 메모와 새 폴더는 지금 프로젝트에 만들어집니다.
   - 프로젝트 이름 바꾸기를 지원합니다. 삭제는 **비어 있을 때만** 가능합니다(메모를 실수로 잃지 않게).
   - 메모를 다른 프로젝트로 옮기는 기능을 제공합니다. 옮길 때 폴더는 대상 프로젝트의 같은 경로로 갑니다.
4. **서버** (마이그레이션 008)
   - `projects(id, owner_id, name, created_at, deleted_at, change_seq)` 테이블을 추가합니다. 계정 안에서 살아 있는 이름은 하나만 허용합니다(대소문자 무시).
   - `notes.project_id UUID NULL REFERENCES projects`를 추가합니다. 경로 유일성 인덱스에 프로젝트를 포함합니다.
     같은 경로라도 프로젝트가 다르면 허용합니다.
   - 변경 목록(`GET /notes?since=`)에 프로젝트 변경도 함께 싣습니다. 빈 프로젝트도 다른 기기에 나타나게 하기 위해서입니다.
     편집 임대와 충돌 처리는 메모 단위라 바뀌지 않습니다.
   - API: `GET/POST /api/v1/projects`, `PATCH /api/v1/projects/{id}`(이름), `DELETE /api/v1/projects/{id}`(빈 프로젝트만, 비어 있지 않으면 409).
     메모 저장 요청에 `projectId`를 추가합니다(없으면 기본).
   - n8n 토큰 API: 메모 목록에 `?project=` 필터를 추가하고, 응답에 `projectId`를 넣습니다.
5. **웹 (IndexedDB)**: DB 버전과 저장소는 바꾸지 않습니다(v0.1 호환 규칙).
   - 프로젝트 목록은 기존 `meta` 저장소의 `projects` 키에 둡니다.
   - 메모 레코드에는 선택 필드 `projectId`를 추가합니다. 없으면 기본 프로젝트입니다. 예전 `sync` 필드를 추가한 것과 같은 방식입니다.
6. **데스크톱·모바일 파일 배치**: 파일이 정본이므로 폴더에 프로젝트가 보여야 합니다.
   - 기본 프로젝트는 지금처럼 `Notes/` 바로 아래에 둡니다. **기존 파일은 옮기지 않습니다.**
   - 다른 프로젝트는 `Notes/@프로젝트이름/폴더/폴더/메모.md`에 둡니다.
     `@`로 시작하는 맨 위 폴더는 프로젝트로 읽습니다. 그래서 일반 폴더 이름은 `@`로 시작할 수 없게 합니다(`paths.json` 규칙 추가).
     이미 `@`로 시작하는 폴더가 있으면 업데이트 후 첫 실행 때 알려 주고 이름 변경을 안내합니다. 자동으로 프로젝트로 바꾸지 않습니다.
   - SQLite 인덱스에 `projects` 테이블(마이그레이션 006)을 추가해 이름과 ID를 연결합니다.
     앱 밖에서 `@이름` 폴더 이름을 바꾸면, 메모 이름 변경처럼 내용으로 대응시켜 같은 프로젝트로 봅니다. 애매하면 추측하지 않고 새 프로젝트로 봅니다.
7. **BSD TUI와 자동화(n8n)**: 기본 프로젝트만 보던 기존 동작은 그대로 유지합니다. 프로젝트 선택은 후속입니다.

## 대안과 버리는 이유
- 최상위 폴더를 프로젝트로 보기: 데이터 변경은 없지만, 프로젝트 안 폴더가 1단계로 줄어듭니다(사용자가 선택하지 않음).
- 프로젝트를 이름으로만 저장(ID 없음): 이름을 바꿀 때 모든 메모 경로를 고쳐야 하고, 동기화 중 이름이 겹치면 처리가 어렵습니다.
- 데스크톱 기본 프로젝트도 `Notes/기본/`으로 옮기기: 구조는 깔끔하지만 기존 파일을 한꺼번에 옮겨야 합니다. 중간에 실패하면 위험해서 피합니다.

## 범위·순서 (승인 후)
1. 서버: 마이그레이션 008, `/projects` API, 메모 `projectId`, OpenAPI, 통합 테스트
2. 웹: 프로젝트 선택·만들기·이름 바꾸기·삭제, 메모 옮기기, 프로젝트별 트리·검색, E2E
3. 데스크톱 core: `@프로젝트` 폴더 읽기·쓰기, 인덱스 006, 앱 밖 이름 변경, `make desktop-sync-check`에 프로젝트 항목 추가
4. 문서: 요구사항표에 #30 "프로젝트"를 추가하고, `04_DATA`·`05_SYNC_API`·`03_UX`를 갱신

## 위험
- 동기화 형식이 바뀝니다. 예전 앱은 `projectId`를 모르기 때문에 다른 프로젝트 메모를 기본 프로젝트로 보여 줄 수 있습니다.
  → 서버가 앱 버전을 확인해, 프로젝트를 모르는 예전 앱에는 기본 프로젝트 메모만 내려 줍니다.
- 프로젝트를 지우는 중에 다른 기기가 그 프로젝트에 메모를 만들 수 있습니다. → 서버가 삭제 시점에 비어 있는지 다시 확인하고, 아니면 409로 거절합니다.
