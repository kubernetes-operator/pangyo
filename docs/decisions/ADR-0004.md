# ADR-0004: 데스크톱·모바일 앱 동기화 연결 (장비 등록 + Rust 경유 서버 요청)
- 상태: **승인**, 2026-11-12 (사용자 승인: 설계안대로 진행, 바깥 삭제는 "확인 후 삭제", 서버 주소는 "등록 화면에서 입력")
- 배경: 06단계(ADR-0003)는 웹만 동기화. 서버의 장비 등록(`/pairing/*`)과 장비 토큰(`Authorization: Bearer`)은 있었지만 앱 쪽 연결이 없었음.
- 결정:
  1. **서버 요청은 Rust가 보냅니다.** Tauri 명령 `server_request` 하나로 화면의 API 요청을 대신 보내고 장비 토큰을 붙입니다.
     토큰은 화면(JS)에 넘기지 않으며, 서버 CORS·웹뷰 CSP를 넓히지 않습니다. 허용 경로: `/notes`, `/search`, `/account`, `/info`.
     화면 코드는 `account/api.ts`의 전송 방식(`setTransport`)만 바꾸고 동기화 엔진은 웹과 같이 씁니다.
  2. **토큰 보관**: 데스크톱은 OS 보안 저장소(keyring: Windows 자격 증명 관리자, macOS 키체인, Linux Secret Service),
     모바일은 앱 전용 폴더. 등록 코드는 한 번만 쓸 수 있으므로 **보안 저장소를 쓸 수 있는지 먼저 확인한 뒤** 서버에 보냅니다.
  3. **서버 주소**는 등록 화면에서 입력합니다(https만, 개발용 localhost/127.0.0.1은 http 허용). 저장소·설치 파일에 도메인을 넣지 않습니다.
     웹 계정 화면은 등록 코드 옆에 서버 주소를 보여 줍니다.
  4. **장비 폐기**(웹에서) → 서버 401 → 앱은 동기화를 멈추고 "다시 연결"을 안내합니다. 메모 파일은 그대로입니다.
  5. **앱 밖에서 바뀐 파일**(파일이 정본이므로):
     - 바깥 편집 → 해시로 감지해 `sync.dirty`(올릴 변경)로 표시.
     - 바깥 이름 변경 → 사라진 파일과 새 파일의 내용이 1:1로 같으면 이름 변경으로 보고 ID·세션·동기화 상태 유지. 애매하면 추측하지 않음.
     - 바깥 삭제 → 서버에 올라간 메모는 바로 지우지 않고 `external_deletions`(SQLite 005)에 보관. 사용자가
       **서버에서도 삭제**(임대 + baseVersion 검사, 그 사이 다른 기기가 고쳤으면 지우지 않고 다시 받음) 또는 **다시 받기**를 고릅니다.
     - 열어 두기만 한 메모의 주기 저장은 **세션 기록만** 저장(`save_sessions`) → 바깥 편집을 덮어쓰지 않음.
  6. 앱은 동기화 주기(20초)마다, 그리고 창이 다시 보일 때 디스크를 다시 읽고 동기화합니다. 편집 중(임대 보유, 저장 전 변경)인 메모는 화면 쪽을 유지합니다.
- 범위 밖: iOS(시뮬레이터 빌드만), BSD TUI 앱(08단계), Android Keystore 연동, 서버에서 장비 스스로 폐기(웹에서만).
- 검증: `make desktop-sync-check`(실제 데스크톱 앱 + 로컬 테스트 서버 + 격리 키링, 7개 항목), core·엔진 단위 테스트.
