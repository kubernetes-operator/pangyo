# ADR-0002: 기술 스택 정리 — TypeScript(화면) + Rust(나머지)
- 상태: **승인**, 2026-11-04 (사용자 승인: 서버 Rust 통일, Roo Code 미사용)
- 맥락: v0.1은 JS/Go/Rust(Tauri)/Rust(BSD) 4개 구현으로 같은 규칙(경로·폴더 깊이·파일명)이 중복되고 이미 서로 다름. 웹에는 타입·자동 테스트가 없음.
- 결정:
  1. 화면은 TypeScript + Vite 웹 UI 하나로 웹 PWA와 Tauri가 공유.
  2. 도메인·파일 저장·동기화 프로토콜은 Rust `crates/core`로 단일화하고 Tauri, BSD TUI, 서버가 공유.
  3. 서버는 Go → Rust(axum)로 이전. 기존 엔드포인트(`/healthz`, `/readyz`, `/api/v1/info`)와 미구현 경로 501 응답은 유지.
  4. API 계약은 `packages/protocol`의 OpenAPI 3.1을 단일 원본으로 하고 TS/Rust 타입을 생성.
  5. 개발 진입점은 `Makefile`(`make check`), CI는 GitHub Actions에서 같은 명령 실행.
  6. Roo Code 전용 설정(`.roo/`, `.roomodes`)은 사용하지 않음. 에이전트 공통 규칙은 `AGENTS.md`, Claude Code는 `CLAUDE.md`.
- 유지: 로컬 우선, `.md` 파일이 정본, 요구 #28 승인 전 잠금/자동 병합 미구현(CRDT 포함).
- 비용/위험: Rust 빌드 시간 증가, 서버 컨테이너 빌드 변경, Tauri는 시스템 WebKit/GTK 라이브러리가 있어야 빌드 가능.
- 이전 순서: ① 도구/CI → ② 웹 TS 이전 + Playwright 회귀(IndexedDB 데이터 호환) → ③ `crates/core` + BSD 전환 → ④ 서버 axum 이전 → 로드맵 3단계 재개.
