# ADR-0003: 동시 작성 제한 — A안 (편집 임대 + fencing token + 오프라인 초안) 승인
- 상태: **승인**, 2026-11-09 (사용자 승인. 요구 28, `docs/07_LOCK_APPROVAL.md` 후보 A)
- 결정:
  1. **편집 시작 시** 서버에서 메모별 임대(lease)를 받습니다. 메모를 열기만 해서는 잠그지 않습니다.
  2. 임대는 짧은 TTL(기본 90초)로 주고, 편집 중인 기기가 주기적으로(30초) 갱신합니다. 기기가 꺼지거나 네트워크가 끊기면 TTL 후 자동 해제.
  3. 임대를 새로 받을 때마다 메모별로 증가하는 **fencing token**을 발급하고, 저장(PUT)에는 현재 유효한 token이 있어야 합니다. 임대를 잃은 뒤 늦게 도착한 저장은 거부됩니다.
  4. 다른 기기가 임대 중이면 그 메모는 **읽기 전용**으로 열리고 누가 언제까지 편집 중인지 표시합니다.
  5. **오프라인**에서는 임대 없이 로컬 **임시 초안**으로만 기록합니다. 재접속 시 임대를 받고 `baseVersion`으로 서버 버전을 검사합니다.
  6. 버전이 겹치면 **어느 쪽도 덮어쓰지 않고** 충돌 검토 화면에서 사용자가 고릅니다: 내 버전 / 서버 버전 / 둘 다 보관.
- 범위(06단계): 웹(브라우저) 간 동기화. 데스크톱·모바일 앱은 장비 등록(페어링) 화면을 붙인 뒤 같은 API로 연결(후속).
- 동기화하지 않는 것: 편집 세션 기록, Undo 기록 (기기별 로컬 정보).
- 저장 위치: S3 도입 전까지 본문은 Postgres `notes.content`에 저장 (용량 계산 포함).

## 보완 (2026-11-14, 사용자 승인: "둘 다")
- **최신 내용 받기**: 읽기 전용일 때 그 메모만 서버에서 바로 받음(20초 주기를 기다리지 않음). 상대가 편집을 끝냈으면 바로 편집 가능.
- **여기서 편집하기(편집 권한 가져오기)**: 확인 창 뒤 `POST /notes/{id}/lease`에 `takeover: true` → 서버가 다른 보유자의 유효한 임대를 **새 fencing token**으로 교체.
  - 빼앗긴 기기: 다음 갱신(TTL/3)·저장(423)·가져오기(다른 기기의 새 버전 수신) 중 가장 빠른 때 읽기 전용으로 바뀜.
  - 그 기기에서 아직 올리지 못한 내용은 덮어쓰지도 지우지도 않고, 기존 **충돌 검토**(내 것/서버 것/둘 다)로 보관.
  - 자동 병합은 여전히 하지 않음. 서버는 가져오기를 로그로 남김(`lease taken over`).
