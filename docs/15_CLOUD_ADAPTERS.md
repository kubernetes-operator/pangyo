# 15. 클라우드 어댑터 설계안 (로드맵 07-3) — 결정 대기

## 목표 (docs/05_SYNC_API.md)
- **모드 A — 공용 저장소**: 서버가 메모 본문을 S3 호환 저장소에 보관 (지금은 Postgres `notes.content`).
- **모드 B — 개인 저장소 연결**: 사용자의 S3/WebDAV에 자기 메모를 보관·동기화 (비용은 사용자 부담).

## 제안 순서
1. **ObjectStore 인터페이스** (`crates/core` 또는 서버): `put/get/delete/list(prefix)` + 구현 2개
   - `S3Store` (S3 호환: AWS, MinIO, Cloudflare R2 …) / `WebDavStore` (Nextcloud 등)
   - 테스트: 로컬 MinIO 컨테이너, WebDAV 컨테이너로 계약 테스트 (자격 증명 불필요)
2. **첫 활용처: DB 백업의 NAS 밖 사본** — 매일 백업 Job이 만든 덤프를 외부 S3에 추가 업로드
   (지금 백업이 DB와 같은 NAS에 있는 위험 해소. `docs/09_OPERATIONS.md` 후속 과제)
3. **모드 B: 개인 내보내기/백업** — 사용자가 자기 S3/WebDAV를 등록하면 메모를 `.md` 파일로 주기적 내보내기
   (단방향 → 안정화 후 양방향). 접속 정보는 서버에서 암호화 저장(키는 Kubernetes Secret) 또는 브라우저에만 보관 중 택1.
4. **모드 A 본문 이전**: Postgres → S3 (용량 커질 때). NAS 성능 문제 완화에도 도움.

## 결정이 필요한 것
| 항목 | 선택지 | 비고 |
|---|---|---|
| 백업 외부 사본 저장소 | 외부 S3(R2/S3/B2 등) / 다른 장비의 MinIO / 사용 안 함 | **접속 키는 사용자가 Secret으로 생성** (조직 규칙상 키 생성·입력 불가) |
| 개인 저장소 연결(모드 B) 우선순위 | S3 먼저 / WebDAV 먼저 / 보류 | WebDAV는 Nextcloud·NAS(Synology 등)에서 바로 사용 가능 |
| 개인 접속 정보 보관 위치 | 서버 암호화 저장 / 브라우저에만 | 서버 보관이면 서버가 주기 실행 가능, 브라우저 보관이면 브라우저가 열려 있을 때만 |
