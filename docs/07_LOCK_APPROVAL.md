# 07. 동시 작성 제한 — 사용자 승인 대기 (요구 28)

## 문제 정의
- 같은 메모를 서로 다른 장비에서 동시에 편집하지 않음.
- 네트워크가 끊겼을 때는 다른 장비의 현재 편집 상태를 검증할 수 없음.
- 따라서 **오프라인 완전 허용과 전역적으로 엄격한 단일 편집 보장**은 동시에 달성할 수 없음.

## 후보
| 후보 | 방식 | 오프라인 작성 | 장점 | 단점 |
|---|---|---|---|---|
| A | 서버 임대(lease)+TTL+fencing token | 미연결 시 미확정 로컬 변경만 허용 | 온라인 동시 편집 차단, 장애 복구 가능 | 오프라인 변경 충돌 대기 및 사용자 확인 필요 |
| B | 서버 단일 잠금/서버 연결 필수 | 불가 | 가장 단순한 전역 배타성 | Offline-first 원칙과 충돌 |
| C | 수동 체크아웃/체크인 | 오프라인 체크아웃 후 작성 | 오프라인 장기 편집에 유리 | 반납 누락·장비 분실 시 처리 어려움 |

## 권장(미승인)
A + 오프라인에서 로컬 **임시 초안**만 기록하고 재접속 시 서버 버전 검사.
변경 내용이 겹치면 어느 것도 덮어쓰지 않고 `충돌 검토` 화면에서 사용자 선택.
메모가 열려 있다고 무조건 잠그지 않고 **편집 시작 시 임대**.
